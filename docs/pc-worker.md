# Тесты на ПК из панели VDS

В карточках Freqtrade, Jesse и Hummingbot можно выбрать **VDS / Мой ПК**.
На ПК работают нативные тестовые движки; сервер хранит очередь, итоговые метрики
и журнал запусков. A/B/C/D продолжают работать по своим существующим правилам на VDS.
Это первый этап переноса вычислений, а не перенос всей лаборатории.

## 1. Подготовить Windows

Для Windows 10/11 с 16 ГБ RAM используется Ubuntu 24.04 в WSL2. В PowerShell
от имени администратора:

```powershell
wsl --install -d Ubuntu-24.04
```

Перезагрузить Windows, если этого попросит установка. Открыть Ubuntu, создать
обычного пользователя и пароль. Проверить в PowerShell:

```powershell
wsl --list --verbose
```

У Ubuntu-24.04 должна быть VERSION 2. Если установлена старая WSL без `--cd`,
сначала обновить её: `wsl --update`. Официальные инструкции:
https://learn.microsoft.com/en-us/windows/wsl/install и
https://learn.microsoft.com/en-us/windows/wsl/basic-commands.

Панель показывает память **Ubuntu/WSL**, доступную исполнителю. Она может быть
меньше 16 ГБ физической памяти Windows. Freqtrade/Jesse требуют 3 ГБ всего и
2 ГБ доступно; Hummingbot — 5 и 4 ГБ соответственно. Проверка повторяется перед
каждым запуском. По умолчанию один тест за раз, до двух CPU и одного вычислительного
потока в библиотеках, с низким приоритетом и пределом 45 минут. Это ограничения
исполнителя, а не гарантии требований всех возможных стратегий этих фреймворков.

## 2. Обновить VDS

От root на VDS, заменив `FULL_COMMIT_SHA` на проверенный SHA из сообщения обновления:

```sh
bash /opt/trading-lab-repo/tools/update.sh FULL_COMMIT_SHA &&
python3 /opt/trading-lab-repo/tools/install_control.py --upgrade &&
python3 /opt/trading-lab-repo/tools/pair_pc.py &&
python3 /opt/trading-lab-repo/tools/diagnose_models.py
```

Одобренная миграция принимает только прежнюю зарегистрированную версию контроллера.
Она обновляет и перезапускает **trading-control.service**, сохраняя модельные
обёртки и состояния. Перед записью проверяет хеши и создаёт резервную копию.
При отказе нового контроллера возвращает прежний код. Не перезапускает A/B/C/D
и не снимает их защитную остановку. При установленной идентичной версии повторный
запуск установщика ничего не переписывает.

`pair_pc.py` создаёт архив `/root/trading-lab-pc.tar.gz` с проверенными исходниками
и их SHA-256. API-ключи биржи, состояния моделей и код подключения в архив не входят.

## 3. Передать архив на ПК

В PowerShell на своём Windows ПК:

```powershell
$LAB_PC_ARCHIVE = Join-Path $env:USERPROFILE 'Downloads\trading-lab-pc.tar.gz'
scp root@78.17.187.70:/root/trading-lab-pc.tar.gz $LAB_PC_ARCHIVE
if ($LASTEXITCODE -ne 0) { throw 'Не удалось скачать архив с VDS' }
$LAB_WSL_ARCHIVE = (wsl.exe -d Ubuntu-24.04 --exec wslpath -a $LAB_PC_ARCHIVE).Trim()
if ($LASTEXITCODE -ne 0) { throw 'Не удалось определить путь архива для Ubuntu' }
wsl.exe -d Ubuntu-24.04 --cd '~' --exec tar -xzf $LAB_WSL_ARCHIVE
if ($LASTEXITCODE -ne 0) { throw 'Не удалось распаковать архив в Ubuntu' }
```

Используется существующий SSH-доступ к VDS. Если в Windows SSH работает через
ключ или нестандартный порт, применить те же настройки к `scp`. При первом
подключении проверить fingerprint хоста так же, как при обычном SSH-входе.

При последующих обновлениях сначала остановить тест из панели, дождаться
подтверждения, затем остановить агент Ctrl+C и распаковать новый архив.
Результаты и окружения находятся в отдельной папке и сохраняются.

## 4. Подготовить движки на ПК

В **Ubuntu на ПК**, не в SSH-сеансе VDS:

```sh
sudo apt-get update &&
sudo apt-get install -y python3-venv python3-pip openssh-client &&
python3 ~/trading-lab-pc/tools/worker_setup.py prepare --engine freqtrade --install &&
python3 ~/trading-lab-pc/tools/worker_setup.py prepare --engine jesse --install
```

Окружения создаются под обычным пользователем в
`~/.local/share/trading-lab-worker/envs`. Версии закреплены: Freqtrade 2026.9,
Jesse 3.2.4. Перед регистрацией выполняется реальный импорт нативного API.
Установка использует интернет ПК и может занять несколько минут.

Hummingbot подключается отдельно, после подготовки официального скомпилированного
окружения. Простой `pip install hummingbot` не заменяет это окружение. Команда-шаблон:

```sh
python3 ~/trading-lab-pc/tools/worker_setup.py prepare --engine hummingbot \
  --python /home/USER/hummingbot-env/bin/python --source-dir /home/USER/hummingbot
```

Заменить пути на реальные. `--source-dir` не нужен, если модули уже доступны
Python выбранного окружения. До успешной проверки импорта кнопка запуска отключена.
Инструкция движка: https://hummingbot.org/installation/.

## 5. Подключить ПК к панели

На **VDS** посмотреть отдельный код подключения:

```sh
cat /root/trading-lab-pc-key.txt
```

На **ПК, в Ubuntu**:

```sh
python3 ~/trading-lab-pc/tools/worker_setup.py connect
```

Вставить код в скрытый запрос ввода. Не присылать его в чат. Пароль панели,
SSH-пароль и код исполнителя — разные данные. Код хранится на ПК в конфигурации
с правами 600, на VDS — в виде хеша, с отдельной root-копией для подключения.

В первой вкладке Ubuntu открыть SSH-туннель и оставить его работающим:

```sh
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=2 \
  -L 127.0.0.1:18787:127.0.0.1:8787 root@78.17.187.70
```

Во второй вкладке Ubuntu:

```sh
python3 ~/trading-lab-pc/integrations/worker/agent.py
```

Обновить панель → **Модели**. Появится «Мой ПК подключён» и RAM исполнителя.
Выбрать **Мой ПК** в карточке подготовленного движка и нажать **Запустить тест**.
Запуск подтверждается ответом исполнителя. Браузер можно закрыть; обе вкладки
Ubuntu и сам ПК должны оставаться включёнными. Сон Windows и остановка WSL
прерывают вычисления. Автозапуск после перезагрузки пока не настраивается.

Туннель идёт через существующий SSH на 22. Панель остаётся на 127.0.0.1:8787;
роутер, UFW, Xray, порт 443 и резервный VPN не изменяются. Агент обращается к
панели исходящими запросами; входящий порт на ПК не нужен.

## Отмена, связь и журнал

- Остановить тест можно кнопкой **Остановить**. Запрошенная отмена и подтверждённое
  завершение процесса — разные состояния. Выбор исполнителя блокируется на время теста.
- Через 15 секунд без подтверждённого ответа агент завершает нативную группу
  процессов и сохраняет результат «прерван». При переподключении передаёт его VDS.
  Завершение не объявляется по одному отсутствию связи, повторного запуска нет.
- При перезапуске агента старый тест не возобновляется. Дочерние процессы помечены
  идентификатором задания и завершаются при восстановлении. Итоговый отчёт доставляется
  повторно до подтверждения; одна задача даёт одну запись журнала.
- На VDS сохраняются последние 300 завершённых запусков ПК суммарно по движкам.
  В карточке — 20 последних на выбранном исполнителе. CSV журнала содержит
  `execution=pc/vds`, идентификатор, состояние, параметры и итоговые метрики.
- Нативные файлы сделок и отчёты остаются на ПК:
  `~/.local/share/trading-lab-worker/results/ENGINE/JOB_UUID/`.
  Нативный runner хранит последние 100 тестов каждого движка.
- Базовые стратегии используют существующий фиксированный runner. Freqtrade/Jesse
  запускают исторические тесты; Hummingbot — PAPER по публичному стакану. Наличие
  исполнителя не является оценкой доходности и не разрешает реальную торговлю.

Диагностика на ПК:

```sh
python3 ~/trading-lab-pc/tools/worker_setup.py status
```

На VDS: `python3 /opt/trading-lab-repo/tools/diagnose_models.py`.
Конфигурацию ПК с кодом подключения не выводить и не пересылать. Для смены кода,
после подтверждённого окончания задания: `python3 /opt/trading-lab-repo/tools/pair_pc.py --rotate`,
затем повторить `connect` на ПК.

## Проверки

`tools/test_worker.py` проверяет протокол, отдельную авторизацию, очередь,
изменение памяти, устаревшие поколения, повторы отчёта, отмену, смену сеанса,
неподтверждённую остановку, HTTP-передачу и откат миграции контроллера.
Playwright проверяет выбор ПК, запуск, отмену, блокировку общего слота,
сохранение выбора, журнал и макеты на 320/390/1280 px.
Нативные проверки Freqtrade/Jesse в CI используют закреплённые версии и
синтетические цены. Установку на конкретном Windows ПК, SSH и сетевой PAPER
Hummingbot нужно подтвердить после пользовательского запуска.
