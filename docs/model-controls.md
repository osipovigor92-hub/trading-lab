# Управление моделями и нативные тесты

Вкладка **Модели** заменяет каталог ссылок на четыре карточки A/B/C/D и три
карточки тестовых движков. Статусы берутся с сервера; нажатие кнопки не считается
подтверждением запуска. Принятые команды и ответы движков сохраняются в журнале
управления. Капитал, позиции и число закрытых сделок показываются отдельно.

## Первая установка на NODE-02

Сначала выполнить обычное обновление панели до проверенного полного SHA:

```sh
bash /opt/trading-lab-repo/tools/update.sh FULL_COMMIT_SHA
python3 /opt/trading-lab-repo/tools/install_control.py
```

Если C/D ещё не установлены, после обновления панели сначала выполнить
`python3 /opt/trading-lab-repo/tools/install_research.py`, затем установщик
управления. Это существующая отдельная установка двух PAPER-моделей;
повторный запуск для работающей установленной версии не перезапускает её.

Обновлятор панели не меняет торговые циклы. Отдельный установщик управления
проверяет хеши оригинальных моделей, ждёт паузы без открытых PAPER-позиций до
10 минут и добавляет systemd drop-in с обёрткой. Оригинальные файлы моделей,
балансы и журналы сохраняются. При ошибке установки обёртки удаляются, исходные
описания запуска восстанавливаются; рабочее состояние не откатывается.

Первая установка перезапускает только ранее работающие A/B/C/D в найденной паузе.
У B заново накапливается поток примерно 60 секунд. Повторный запуск установщика
проверяет совпадение файлов и не перезапускает модели. Если подходящей паузы нет,
установка завершается без записи; её можно повторить позже. Если позиция появилась
в коротком окне остановки, миграция отменяется с сохранением её состояния: штатная
защита модели отмечает перерыв наблюдений, фиктивное закрытие не создаётся.

Контроллер слушает только локальный Unix socket. Панель остаётся непривилегированной.
POST требует токен текущей сессии панели, JSON и проверку поколения команды.
Брокер принимает только перечисленные модели и тестовые службы. VPN, Xray,
firewall, SSH, HTTPS и сетевые порты не изменяются.

## Что делают кнопки A/B/C/D

| Действие | Поведение |
|---|---|
| Включить | Разрешает новые входы после прогрева условий. Не снимает защитную остановку. |
| Отключить | Запрещает новые входы; существующая позиция продолжает штатные выходы. После закрытия статус «Отключена». |
| Перезапустить | Дожидается штатного закрытия позиции, очищает подтверждения входа и повторяет прогрев. Капитал, комиссии, риск-лимит и сделки сохраняются. |
| Открыть журнал | Переходит к журналам закрытых сделок этой модели. |

Это перезапуск логики входов, а не принудительный SIGKILL процесса. B продолжает
собирать стакан и ленту при отключённых PAPER-входах: C/D используют этот поток.
C и D управляются независимо, хотя работают в одной службе. Защитная остановка
с незакрытой позицией запрещает включение/перезапуск. Лимит потерь не сбрасывается
и не снимается перезапуском. Если остановлена сама служба, карточка показывает это
отдельно; включение запускает только соответствующую разрешённую службу.

## Внешние движки

Нативные движки **не входят в лёгкую установку управления**. Карточка «Не подготовлен»
не является работающим ботом. После подготовки появляются кнопки запуска,
остановки и повторения ограниченного теста. Одновременно допускается один внешний
тест. Для каждого запуска хранятся идентификатор, параметры, состояние, метрики,
нативные результаты и журнал CSV; сохраняются последние 100 запусков.

| Движок | Доступный тест в этой интеграции | Результат |
|---|---|---|
| Freqtrade 2026.9 | Нативный исторический backtest, EMA20/50, BTC/USDT:USDT Bybit, 5m, семь полностью закрытых дней UTC, капитал 600, номинал 100, комиссия 0,055% на сторону | Число сделок, net, win rate, profit factor, просадка и нативные сделки |
| Jesse 3.2.4 | Бесплатный `jesse.research.backtest`, EMA20/50, BTC-USDT Bybit, 5m из непрерывных 1m свечей, те же семь закрытых дней и комиссия | Число сделок, net и нативные метрики/сделки |
| Hummingbot | Нативный PaperTradeExchange + PureMarketMakingStrategy, публичный Binance BTC-USDT spot, 20 минут, котирование по 0,1% от mid, виртуальный портфель 600 USDT | PAPER-исполнения и изменение оценки портфеля; это не число завершённых round-trip сделок |

Параметры EMA — исходный неоптимизированный пример, не доказанно прибыльная модель.
Freqtrade и Jesse используют разные исполнения и правила выхода; результаты
семи дней нельзя трактовать как контролируемое сравнение доходности платформ.
Исторические тесты не моделируют очередь лимитных заявок. Jesse не добавляет
фиксированное проскальзывание. Hummingbot симулирует исполнения, а оценка капитала
включает переоценку начального запаса BTC. Публичная ликвидность не гарантирует
реальное исполнение. API-ключи и реальные ордера эти адаптеры не принимают.

У бесплатного Jesse PAPER/live-режим не входит в эту интеграцию; используется
именно открытый исторический research API. Hummingbot требует готового нативного
окружения с его Cython-компонентами. Установка одного названия пакета не считается
подготовкой: проверяются импорты нужных классов и версия движка.

### Требования и подготовка

Официальный Freqtrade рекомендует минимум 2 ГБ RAM / 2 vCPU; Hummingbot — 4 ГБ RAM
на экземпляр. Для этой панели принята более строгая политика с резервом памяти:
**3 ГБ всего для Freqtrade/Jesse и 5 ГБ для Hummingbot**. Требование Jesse здесь —
политика нашей интеграции. Перед каждым запуском дополнительно проверяется доступная
память: 2 ГБ или 4 ГБ соответственно. На NODE-02 с 1 ГБ подготовка прекращается
до установки зависимостей, а кнопки тяжёлых тестов остаются недоступными.

На сервере с достаточными ресурсами и `python3-venv`:

```sh
python3 /opt/trading-lab-repo/tools/prepare_engine.py --engine freqtrade --install
python3 /opt/trading-lab-repo/tools/prepare_engine.py --engine jesse --install
```

Для уже подготовленного изолированного Python-окружения вне `/root`:

```sh
python3 /opt/trading-lab-repo/tools/prepare_engine.py --engine hummingbot --python /opt/hummingbot-env/bin/python
```

Последний путь — пример; должен указывать на настоящее установленное окружение
Hummingbot. Если официальный проект скомпилирован в отдельном каталоге и не
установлен в `site-packages`, добавить `--source-dir /opt/hummingbot` с настоящим
путём к этому проекту. Проверка импорта всё равно обязательна. Docker, nginx,
VPN и firewall этот установщик не настраивает. Службы
тестов не включаются в автозагрузку, не перезапускаются автоматически и имеют
ограничения памяти, CPU и времени. Отмена завершает группу дочерних процессов.
Отмена/ошибка сохраняются в журнале с последними доступными метриками.

## Проверки

`tools/check.py`: пауза, завершение позиции по прежним правилам, прогрев, сохранение
баланса/журнала, риск-лимит, общий поток B для C/D, недопустимые команды, устаревшие
поколения, токен, единственный внешний тест и защита установленного кода.
Playwright проверяет кнопки, отказ сервера, прогрев, отмену/повтор теста, CSV и
адаптивный интерфейс на 320/390/1280 px на явно синтетическом стенде.
Дополнительные CI-задачи устанавливают закреплённые Freqtrade/Jesse и проверяют
нативные API на синтетических ценах. Это проверка совместимости, а не доходности.
Hummingbot проверяется импортами при регистрации; его сетевой PAPER-прогон нельзя
считать выполненным до подготовки настоящего окружения и запуска пользователем.
