# Задержки источников и восстановление избранного

Исправления поверх d3b36474:

- Запросы каталогов и стаканов раньше, при занятом общем слоте, откладывались до
  следующего вызова snapshot. Частые каталоги могли повторно занимать слот раньше
  стакана. Теперь ограниченная FIFO-очередь хранит запрос и запускает его после
  завершения предыдущего. Лимиты исполнения прежние: два потока, четыре задания,
  не больше одного задания каталогов/стаканов одновременно. Очередь до 96 ключей,
  повтор ключа не меняет его место, вытесненные записи не исполняются.
- Монитор плотностей забирает завершённые снимки всех наблюдаемых пар каждую
  секунду через peek_book без новых сетевых запросов. Возраст источника остаётся
  исходным; ошибки и старые снимки не становятся свежими.
- Прогрев минутных свечей чередует первый слот со стаканом для алертов.
- Алерты показывают имеющиеся причины ожидания даже без полного подтверждения.
- После явного HTTP 409 очередь избранного может объединить последующие изменения
  с отклонённой командой: исправляющее удаление больше не стоит за ней бесконечно.
  После потери ответа исходный ID сохраняется. Отдельная кнопка позволяет явно
  отменить несохранённые локальные изменения и загрузить общий список сервера.
- HTTP-ошибки и ошибки записи избранного показываются подробнее. Автоматического
  стирания файла, сброса счёта или ослабления контроля свежести нет.

Для проверки установленной панели:

```bash
python3 /opt/trading-lab-repo/tools/diagnose_feeds.py
```

Команда читает /api/monitor-health: время и ошибки источников, охват плотностей,
число избранных и последнюю ошибку записи. Выводит также лимиты памяти/задач и
число рестартов systemd. Токены не возвращаются, фильтры и наблюдение не меняются.
Проверка не доказывает успешную запись, если пользователь ещё не пытался сохранить.
Причины сетевых отказов и прав доступа на конкретном сервере требуют этого вывода.
