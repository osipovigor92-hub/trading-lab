Операционный обзор A/B/C/D, общего тестового слота и исполнителей уже добавлен

## Готовое поведение

Центр расположен до подробных карточек A/B/C/D. Здесь выбирают Freqtrade,
Jesse или Hummingbot и исполнитель: Мой ПК / VDS. Выбор согласован с карточкой
движка и сохраняется в браузере. Для уже привязанного ПК первоначально выбран
ПК, если пользователь ещё не сохранял другой выбор.

Запуск, повтор и остановка используют существующий контроллер и его разрешённые
действия. Команда «принята» ещё не означает, что процесс работает: центр ожидает
подтверждение, удерживает слот и блокирует повторные старты. Запуск на одном
исполнителе блокирует второй исполнитель и остальные движки. Остановка остаётся
доступной для потерявшего связь задания, если контроллер разрешает её; слот
освобождается после подтверждения. Процент готовности не вычисляется.

В центре показаны только метрики последнего завершённого запуска выбранного
движка на выбранной машине. Предыдущий результат явно отделён от выполняющегося
теста. Отмена не наследует метрики более раннего успешного теста. Freqtrade/Jesse
показывают Net P&L, закрытые сделки, Profit Factor и просадку; Hummingbot —
изменение оценки портфеля, PAPER-исполнения и оборот. CSV содержит общий журнал
выбранного движка с указанием исполнителя.

ПК показывает связь, последний ответ и доступную RAM. Нет связи с контроллером
и подтверждённый офлайн ПК различаются. После восьми секунд без свежего ответа
контроллера кнопки отключаются, слот не обозначается свободным и RAM не выдаётся
за текущую. Архивные результаты остаются подписанными. Для уже привязанного ПК
подсказка предлагает проверить туннель 18787 и агент, без повторной регистрации.

## Проверки этапа

```sh
python tools/check.py
node tools/test_engine_center.cjs
node tools/visual-check.cjs
node tools/test_chart_interactions.cjs
```

Новые модульные проверки охватывают свежесть, общий слот, потерю связи,
незавершённую команду и разделение результатов по исполнителям. Браузерный
сценарий проверяет центр на 320/390/1280 px: запуск и отмену на ПК через
демонстрационный контроллер, CSV, сохранение выбора, малый VDS, офлайн/потерю
ПК, устаревший ответ и HTML вместо JSON. Снимки используют подписанные
синтетические данные и не показывают доходность пользовательского бота.

## Применение и следующая контрольная точка

Из рабочих исходников изменяются только `models.js` и `models.css` панели.
Штатный updater применяет проверенный полный SHA. Контроллер, исполнители,
модели, балансы и базы не требуют миграции для этого этапа.

На VDS пользователь запускает:

```sh
bash /opt/trading-lab-repo/tools/update.sh FULL_COMMIT_SHA &&
python3 /opt/trading-lab-repo/tools/diagnose_models.py --json
```

После обновления открыть панель через существующий туннель
`http://127.0.0.1:8787` и проверить центр. Следующая незавершённая проверка
из прежнего плана: нативный Freqtrade на уже подключённом Windows 11 / WSL2
с возвращением реальных тестовых метрик в панель. Туннель 18787 остаётся
открытым. Не повторять `prepare`, `connect` или `pair_pc.py --rotate`.
Если ранее подготовленный архив совместимости Freqtrade ещё не доставлен на ПК,
сначала завершить его доставку по существующей инструкции, сохранив окружения
и привязку. Прямого доступа разработчика к пользовательскому ПК/VDS нет.
Проверки в CI и preview не заменяют этот запуск.

После проверки Freqtrade продолжить согласованные проверки C/D и остальных
внешних движков. Hummingbot запускается после регистрации скомпилированного
окружения. Этот этап не включает реальную торговлю.
