# Обновление существующего NODE-02

## Доступ к приватному GitHub

На сервере создать отдельный SSH-ключ для чтения. Добавить его публичную часть в
GitHub → trading-lab → Settings → Deploy keys → Add deploy key.
**Allow write access выключено.** Приватный ключ остаётся на сервере.
Ключ другого проекта, например VPN, не использовать.

При первом SSH-подключении проверить отпечаток GitHub по официальной странице
https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints
Не отключать StrictHostKeyChecking.

Клонировать в отдельный каталог `/opt/trading-lab-repo`, используя этот ключ.
Не клонировать поверх `/opt/trading-panel` или каталогов ботов.

## Обновление

Из чистой копии репозитория после проверки конкретного коммита:

```sh
bash /opt/trading-lab-repo/tools/update.sh FULL_COMMIT_SHA
```

`FULL_COMMIT_SHA` — полный идентификатор проверенного коммита, который передаётся
в команде обновления, а не имя движущейся ветки. Доступ SSH к origin должен быть
настроен в этой копии через `core.sshCommand`.

Первый запуск сверяет все импортированные файлы с `deploy/baseline.json`.
Если сервер совпадает с исходным экспортом, регистрируется версия без перезапуска.
Если файлы изменены, запуск останавливается: нужен новый экспорт и сверка.

Последующие запуски сравнивают установленную версию с новой. Разрешены изменения
только `src/trading-panel`, `src/trading-report`, `src/trading-signals`.
Изменения торговых моделей, LIVE, сканеров или systemd units блокируются и требуют
отдельной миграции. Все позиции и рабочие базы остаются на сервере.

Перед записью исходники копируются в `/var/lib/trading-lab-deploy/backup-*`.
Файлы заменяются атомарно по одному. Перезапускаются только затронутые разрешённые
службы. Для отчётов останавливается таймер и выполняется новый отчёт.
При ошибке записи, запуска или HTTP-проверки код автоматически восстанавливается.
Рабочие JSON/SQLite данные не откатываются и не обнуляются.

Это не общая транзакция файловой системы: отключение питания или SIGKILL может
прервать процедуру. Следующий запуск обнаружит расхождение и остановится; для
восстановления использовать сохранённую резервную копию после проверки состояния.

## Ограничения проверки

HTTP-проверка подтверждает доступность JSON и страниц. Она не доказывает
доходность стратегии, свежесть всех рыночных источников или правильность дизайна.
Торговые модели никогда не перезапускаются этим скриптом, включая откат.
