# Product: Trading Lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

The existing panel uses HTML, CSS, browser JavaScript and a Python HTTP server. Exchange charts use the locally served official TradingView Lightweight Charts 5.2.1 bundle; no chart service or CDN receives the selected symbols. Browser WebSockets subscribe directly to the selected exchanges' public candle and ticker channels. Verified closed history, derived measurements and orderbook snapshots share a bounded Python background cache. This documents the current stack; it does not introduce a framework or deployment change.

## Users

The project owner follows crypto coins for manual trading. Their stated problems are alerts that disappear and a screener whose changing rank moves coins away from the place they were watching.

## Product Purpose

Find observable market activity, keep chosen coins easy to follow, explain the current setup, and let the user check risk before making a manual decision. The activity index measures observations; it is not a probability of profit.

## Operating Context

The website has five pages: **Скринер**, **Плотности**, **Алерты**, **Позиции**, and **Настройки**. The user's later request for a screenercrypto.ru-style chart screener and densities expands the earlier four-page assistant. Tests, models, journals, an independent orderbook page and Live remain removed from the website. The observation event feed remains part of the table screener and alerts workflow.

The chart screener uses public WebSocket display updates and verified REST history for Binance, Bybit, OKX, Gate and Bitget USDT perpetual contracts. The density monitor uses their public REST adapters. Exchange and symbol together identify a source; the same coin on two exchanges is not a shared quote. The existing detailed activity table continues to use Bybit public REST data for linear USDT perpetual contracts. Tickers cover the top 100 valid contracts by 24-hour turnover; expiry and pre-listing contracts are excluded. A watched symbol still has to be present in this bounded universe.

`tools/preview.py` uses isolated synthetic fixtures and an isolated temporary PAPER ledger; its demo flag disables external chart streams. Its visible demo banner and screenshots must not be presented as live exchange evidence. Observation timestamps use the browser's locale; exchange-chart candle readouts and time axes use UTC. Freshness checks retain original source timestamps where supplied; OKX candle streams identify receipt time explicitly because their bar timestamp is an opening time.

## Capabilities and Constraints

- **Chart refresh and overlays:** the chart TTL starts background revalidation without clearing still-valid proof: original receipt age <=75s, unchanged expected closed boundary and no refresh error. Catalog revalidation retains original source/receipt proof <=60s. Two of the four existing backend admission slots remain available for charts, with two HTTP workers; the browser deduplicates source requests and loads visible plots before auxiliary metric candles. Candle proof is independent of catalog quote proof. The expanded chart supports browser-local support/resistance annotations (12 per exchange-symbol pair, 48 pairs), entry by price or native plot click, deletion and explicit price-scale fit. Density overlays read only the selected source, display up to three levels per side >=100,000 USDT within 5%, and require packet age <=30s and observation age <=25s. Unavailable levels become unconfirmed and confirmed missing levels disappear. Density-page polling pauses behind the chart dialog and restores its filter scope when it closes. Annotations and overlays send no trading commands.
- **Live chart display:** public browser streams provide the exchange's native forming candle and a separate last-traded-price line. Quote subscriptions can start from the catalog's verified `native_symbol` while closed history is queued. An open candle is appended only to its matching contiguous closed history and is labelled as forming; it never changes REST proof or enters EMA20/50, VWAP60, NATR or alerts. At most 13 source keys cover 12 grid tiles and one dialog. The provider uses only needed venue groups, with a ceiling of six sockets because OKX candles and tickers have separate addresses. Subscriptions are deduplicated, rendering is coalesced over 250ms, hidden pages close their streams, and reconnects back off from 2 to 30 seconds plus jitter. Quote proof expires after 10 seconds; candle proof after 75 seconds and at a period change. A native closing candle has only a ten-second publication overlay window. Disconnects immediately clear live samples. Only five fixed WSS hosts are permitted by the dashboard CSP. Gate live contract volume stays unknown rather than masquerading as base quantity; OKX candle generation time remains null with an explicit receipt-time origin.
- **Adaptive closed-history updates:** the visible catalog is checked every 5 seconds, matching its 5-second backend TTL. Chart reads use a 15-second idle cadence shortened by the original receipt hint or next close + 2 seconds. A continuous series exactly one closed bar behind during seconds 2–10 is checked at most once per second per source and described as updating the closed candle. The old series remains unconfirmed for current metrics, and timestamps stay unchanged. Real failures retain explicit error wording and a 5-second retry. Live display does not conceal an unavailable closed-history source or guarantee upstream latency.
- **Efficient rendering and history transport:** unchanged snapshots skip native series-data and size calls; forming ticks update their own candlestick incrementally and preserve historical viewport/crosshair state. Python direct HTTPS reads reuse at most two idle connections per venue for up to 30 seconds, within the existing two-request global limit. Certificate verification, six-second timeout, 4 MiB limit, fixed public GET paths and redirect refusal remain enforced. Configured proxies retain the previous urllib route; a failed GET is not silently retried inside the transport.

- **Chart screener:** the default view is a grid of 4/6/9/12 charts, with exchange, timeframe, search, watch and metric controls. Metrics include 24h turnover/change/trades, closed-candle NATR 5m/14 and 1m/30, and 5m change. Missing provider trade counts remain unavailable. Only verified loaded candle packets contribute derived metrics; sorting is explicit and tile order stays pinned. A dialog expands a source-specific chart; the Bybit dialog can open the existing activity table and risk calculator.
- **Interactive candles:** grid and expanded exchange charts share one native candlestick renderer, right price scale, time axis, crosshair and OHLCV candle readout. Periods are 1m, 5m, 15m, 1h, 4h and 1d. Mouse drag, wheel/pinch zoom and focused keyboard controls (`+`, `−`, arrows and `Home`) change the local viewport without fetching more history. A historical viewport preserves its UTC anchors as the bounded window rolls; a latest viewport follows new candles. The dialog can show a separate base-volume pane and EMA20/50 plus VWAP60 lines, calculated from loaded closed candles. The forming candle and last-price line remain separate display observations; older-history loading is not provided. Source switches clear the previous source. Stale closed candles remain readable with explicit unconfirmed status and contribute no current metric.
- **Densities:** display public bid/ask levels, default size at least 100,000 USDT and distance 0–5%, exchange/include/exclude/side/size/distance filters, per-contract level limits and size/distance/age sorting. A table and distance radar share the real row data. Backend tracking starts at 50,000 USDT, scans at most 20 contracts with watch priority and exposes actual coverage. The browser polls only the visible density page every five seconds; the monitor visits a full bounded shortlist periodically, normally in ten seconds. Watched pairs preserve exchange identities and are capped at 20.
- **Density continuity:** one-hour cards require the backend's active stable flag and at least 3,600 seconds of sequential fresh observations. The browser never advances that age. Source gaps, outages, restart and levels outside fetched depth interrupt confirmation; two new covered misses confirm disappearance. Confirmed missing episodes remain separately visible, including repeated episodes at the same price. Periodic snapshots cannot prove a level stayed present between checks. Failed reads retain prior levels as unavailable. No density control sends a trading command.
- **Activity table:** search, scenario filters, minimum activity, turnover and spread controls, three sort choices, up to eight watched coins, a selected-coin chart, indicator groups, setup reasons, activity breakdown and a manual risk calculator.
- **Stable order:** the default keeps existing visible symbols in their remembered order while values update. New symbols append. The user can explicitly re-sort or enable automatic ordering. Selection and watch entries persist in the browser when storage is available.
- **Bounded analysis:** watch entries get priority. Remaining slots use a ticker discovery proxy, `min(|change24_pct|,20)/20 + min(range24_pct,30)/30`, then turnover and symbol as tie-breakers. This proxy is distinct from the confirmed activity index. The worker shortlist remains at most eight pairs, with two workers, at most two outstanding upstream jobs and 24 cached packets; selected-chart requests reuse the same cache. Multiple browser requests share the latest shortlist for 30 seconds.
- **Closed-candle evidence:** assistant setups use 1-minute closed candles from a verified contiguous window of 60–180 bars. EMA20/50 use an SMA seed; RSI14 and ATR14 use Wilder smoothing. VWAP60 is exchange quote turnover divided by base volume over 60 bars, not a session VWAP. RVOL5/20 is mean base quantity over the last five bars divided by mean quantity over the preceding 20 bars. A displayed 5m/15m/1h chart does not change the assistant's 1m signal timeframe.
- **Activity index:** four independently rounded components sum to 0–100. Each component is `floor(clamp(value/cap,0,1) × maximum + 0.5)`: RVOL5/20 has cap 3 and maximum 40; 5m range has cap 1.5% and maximum 30; absolute 5m change has cap 1% and maximum 20; 24h turnover has cap 100 million USDT and maximum 10. Direction is separate from the score. Thresholds are explicit heuristics, not a performance claim.
- **Setup gates:** momentum requires the EMA/VWAP directional condition, RVOL at least 1.5, 5m range at least 0.2%, and signed 5m change of at least 0.1%. Breakout uses a first closed crossing beyond the previous 20-bar range with a 0.1 ATR buffer and sufficient relative volume. Extension beyond 1.5 ATR from the original breakout boundary blocks the continuing impulse until the close re-enters that boundary; this context is derived from the bounded candle window. Momentum episode memory is independent of the displayed breakout label. RSI is context and a late-entry warning, not an instruction to reverse a trend.
- **Assistant freshness:** Bybit assistant quote age is at most 45 seconds, chart age 75 seconds and closed-candle age 120 seconds, with a two-second future-clock tolerance. Missing, incomplete, misaligned, stale or failed-refresh sources produce pending analysis with no current score or positive assistant signal. Browser display streams cannot refresh this proof. Source-time rollback does not create a new transition. Pending values are shown as dashes and an explanation.
- **Directional alerts:** confirmed Bybit 1m breakout/momentum up setups expose LONG and down setups expose SHORT through a source-bound nullable recommendation with reason, invalidation, signal identity and original expiry. Liquidity-only events, proximity to a level, watch/pending and source rollback carry no recommendation. Cards, the compact screener feed and explicit browser notifications show direction; a direction filter selects LONG, SHORT or undirected events. Archived copies use a neutral saved-observation label and carry no current recommendation; the main feed retains each observation with a history label after its current validity expires. Current conditions separately expose the continuing setup only while its original quote/chart/candle proof remains valid. Signal prices are observations; entry, stop, target and position sizing remain manual.
- **Alerts:** a current event is short lived, with source-dependent validity and a maximum 30-second lifetime. The browser retains up to 50 captured events for 24 hours; expiry changes the current/history label instead of deleting the observation. Clearing history does not hide still-current events or re-arm their notifications. Initial connection, source gaps and repeated polls do not replay the same episode notification. Sound and browser notifications require explicit browser controls; they require the browser to remain open.
- **Risk calculator:** LONG/SHORT, capital, risk percentage, entry, stop, target, fee and slippage are manual inputs. The estimate includes costs on both sides, limits notional to the entered capital and explains that funding and actual orderbook execution are excluded. Defaults are editable assumptions, not a statement of the user's actual exchange tariff. Preparing a PAPER draft requires a valid estimate, reward/risk of at least 1.5, a fresh chart and quote, and current price within 0.02% of the entered price; risk must be at least 0.01% and slippage must be nonnegative. Preparation transfers a zone of entry ±0.02%, the manual stop/target and cost assumptions to the Positions page, with a maximum notional of 100 USDT. It does not open a position.
- **Positions:** the existing manual PAPER account is separate from real trading: one position, initial capital 600 USDT, no leverage. The user reviews the prepared draft and explicitly confirms a virtual entry. The server checks current price, orderbook and risk against its current balance before virtual entry. A missing or unavailable PAPER installation is displayed explicitly. No real orders are sent by this workflow.
- **Settings:** density and starting page are browser preferences. Market filters and observation controls remain in their respective pages.

Removing a website section does not delete its backend service, ledger or historical data. Orderbook data remains an internal execution guard for manual PAPER even though there is no orderbook page.

## Evidence on Hand

Focused chart-speed measurements on 2026-10-11 used real Chromium and the bundled Lightweight Charts 5.2.1 renderer: 100 unchanged snapshots previously caused 100 native resize calls and 400 series `setData` calls; the updated path caused neither. Two forming ticks caused two candlestick `update` calls. The same local loop measured 69.7ms before and 56.8ms after, which describes renderer work rather than exchange latency. A separate deterministic HTTPS model used eight GETs, 120ms per TLS setup and 40ms per response: connection reuse reduced model cost from 1.28s to 0.44s without reducing validated reads. These measurements are bounded engineering evidence, not production timing guarantees.

A read-only public WebSocket probe on 2026-10-11 listened for 20 seconds on all six provider sockets and received BTC five-minute candles and quotes from all five venues. Frames that supplied generation time had observed source-to-receipt delays of 0.04–0.56s in that run. OKX candle messages supplied only opening time, so their measurement remains receipt-based. This establishes point-in-time public access from the probe environment, not availability or latency from every user's browser or the VDS. Current browser finish review and exact-head CI are recorded separately after completion; the measurements do not claim those checks have passed.

## Table columns and grid density controls

The table supports explicit ascending/descending header sorts and inclusive local min/max ranges for price, signed 24h change, activity, RVOL, RSI and spread. Unknown measurements sort last in either direction and cannot satisfy an active range. Invalid ranges are explained. An explicit sort rebuilds pinned order once; subsequent quote updates preserve row positions, watch, selected coin and manual risk inputs. Browser preferences persist.

Each native grid card has a source-specific Плотности toggle. Enabled visible cards share one grouped cache request every two seconds, at most twelve pairs on one venue. Bid/ask lines show notional in USDT, at least 100,000 and within 5%, at most three per side. Expired or failed observations retain grey unconfirmed lines; current confirmed removal removes them. The grid scope pauses behind a dialog, table or hidden page. Public density data does not establish an owner's intention or a directional trade signal.

The performance extension drains completed density books every second without adding upstream jobs, displays fresh new levels immediately, and skips hidden radar/history construction. Bybit quote and analysis packets share their original timestamp; pending analysis is checked every second. A persistent rotating chart/book queue prevents slow successful refreshes from starving watched books. The browser response cache is bounded to 48 entries with its original non-sliding 750ms lifetime.
